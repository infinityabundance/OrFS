  honest `ENOSYS` stubs.

### What actually works today

```sh
orfs init <dir> [--segment-size N]   # create volume.meta + genesis
orfs inspect <dir> [--json]          # identity, segments, root, accounting
orfs verify [--deep] <dir>           # authoritative structure checks
orfs recover <dir>                   # quarantine an abandoned tail, report
```

* A root `R` is a logical committed end offset; every published root is a
  complete transaction boundary.
* Torn or uncommitted tails are retained and quarantined, never truncated;
  writes continue in a fresh segment.
* Replay from any committed prefix is deterministic.

## Phase 2 — Transactions, commit sequencer, durability, fault injection

**Complete** (see also `docs/TRANSACTIONS.md`).

### Delivered

* `src/transaction.rs` — the transaction model: explicit states (`PREPARED`,
  `RESERVED`, `SUBMITTED`, `DATA_COMPLETED`, `COMMIT_COMPLETED`, `PUBLISHED`,
  `DURABLE`, `FAILED`) with an enforced forward-only transition relation; typed,
  CRC32C-checked payload codecs for `TX_BEGIN` (28 B), `TX_COMMIT` (72 B, with a
  BLAKE3 bracket checksum and commit sequence number), and `TX_ABORT`
  (variable-length, with a reason); and a `TransactionBuilder` that validates all
  arguments before anything is reserved.
* `src/commit.rs` — the single authoritative commit sequencer:
  validate → build → reserve → write data → wait for completions → write/validate
  `TX_COMMIT` (read back from the backing store) → publish the in-memory root →
  reply per durability mode. The root is published **only** after `TX_COMMIT` is
  fully written and validated, so no reader can observe a partial transaction.
* Durability profiles with documented acknowledgment contracts:
  `sync` (ack after `fsync`; `DURABLE`), `ordered` (ordered + published; no
  commit-time `fsync`; `PUBLISHED`), `batched` (coalesced sync points with an
  explicit contract). No profile claims power-loss durability
  (`claims_power_loss_durability()` is always `false`).
* `src/failpoints.rs` — a reusable failpoint system behind the `failpoints`
  Cargo feature (compile-time no-op by default), with thread-local runtime
  control via environment variables or `configure`/`configure_one`/`clear`, and
  `error`/`abort` actions, at all ten required injection points plus directory
  synchronization.
* `tests/transaction_model.rs` — builder/codec validation, the state machine,
  bracket verification, durability contracts, rollover, all failpoints
  in-process (terminate → drop → reopen → verify), and randomized
  transaction/failpoint sequences (proptest).
* `tests/crash_recovery.rs` — **process-crash** tests: a child process is killed
  with `SIGABRT` at each failpoint and the volume is reopened in an independent
  step; every recovery invariant is checked and recorded as evidence.
* `tests/support/mod.rs` — shared recovery-verdict helpers.

## Phase 5 — Asynchronous backing I/O (`io_uring`)

**Complete** (see also `docs/IO_URING.md`). This is research §17 **Domain A
only**: the backing store. The FUSE transport is unchanged (still `/dev/fuse`).

### Delivered

* `src/uring.rs` — the sole `io_uring` interface: bounded ring creation with
  runtime capability probing; submit-and-wait with a stable `user_data` per
  operation; positional `read`/`write`/`fsync` primitives; a concurrent read
  batch (Ring R) and a bounded write batch (Ring W); an **explicit ordering
  primitive** (`write_then_fsync_ordered`) and durability barrier
  (`fsync_order_barrier`) built from `IOSQE_IO_DRAIN`; cancellation; and a
  teardown that drains. Negative results, short writes, partial reads, `EINTR`,
  cancellation, queue saturation, and resource exhaustion are all handled.
* `src/buffers.rs` — registered-buffer / buffer-pool management with strict
  lifetime tracking: pin (borrows the pool, so it cannot be dropped), explicit
  in-flight accounting, and release refused while pinned or in flight. Cancellation
  is never treated as proof a buffer is safe to release.
* Integration: `Log` now routes authoritative writes, reads, and `fsync` through
  a `BackingEngine` (`Sync` or `Uring { Ring W, Ring R }`); `Log::read_range`
  issues multi-segment reads as one concurrent batch; `Log::sync` uses the
  `IO_DRAIN` durability barrier. The commit protocol (`src/commit.rs`) is
  logically unchanged — the write order it already depended on is now established
  by completed-CQE barriers rather than submission order.
* `orfs mount --backing-io uring|sync` genuinely selects the engine. When
  io_uring is unavailable it falls back to sync and **reports the real outcome**
  (mount message, `OrfsMount::backing_io_used`, `orfs doctor`). All silent
  fallback claims are removed.
* `scripts/container-uring-test.sh` + `scripts/uring-probe.c` — a runnable
  io_uring court. The default seccomp profile is **proven** to block
  `io_uring_setup` (EPERM); the script detects this and adds
  `--security-opt seccomp=unconfined` only when needed, then runs with
  `ORFS_REQUIRE_URING=1` so a fallback is a hard failure.
* `benches/backing_io.rs` — an honest sync-vs-uring micro-benchmark for
  sequential append and random read (single-op and batched).
* Carry-over fix (test-only): in `tests/namespace_model.rs` the reference model's
  `NoReplace` rename branch now rejects renaming a directory into itself or a
  descendant, matching OrFS's `DirectoryCycle` (the `Ordinary` branch already
  did). Surfaced by the randomized model test; counterexample retained in
  `tests/namespace_model.proptest-regressions`.

### Ordering mechanism (chosen and verified)

Submitting a write SQE before an `fsync` SQE does not order them. OrFS uses
(a) a **completion barrier** — the commit sequencer validates each write's CQE
before the next step (as Phase 2 already required) — and (b) an explicit
**`IOSQE_IO_DRAIN`** barrier for durability points, machine-checked by
`OrderedReport::fsync_after_write_every_round` in the test and recorded in
`evidence/performance/backing-uring.json`. `IOSQE_IO_HARDLINK` is deliberately
not used (it would continue past a failed dependency).

Yes, in `scripts/container-uring-test.sh`: `uring_available=true`,

## Phase 6 — Historical snapshots and index checkpoints

**Complete** (see also `docs/SNAPSHOTS.md`).

### Delivered

* `src/snapshot.rs` — `Snapshot` + `HistoricalRoot`: a historical root reference
  is `(volume UUID, committed end offset)`; `open_snapshot(volume, root)` (and
  `Snapshot::open` / `Snapshot::open_dir`) validate that the root is a committed
  transaction boundary (I3) and reconstruct the namespace by replaying the
  committed prefix `L[0:R]` (`Index::from_log`). Reads (lookup, `getattr`,
  `readdir`, `readlink`, `read`, xattrs, `seek_data_hole`) return historical
  contents, sizes, metadata, directory entries, symlink targets, and permissions.
  The `Snapshot` owns an `Arc<Log>` read handle and a `RootPin`.
* `src/checkpoint.rs` — `INDEX_CHECKPOINT` recovery: discover candidate
  checkpoints with a **header-only** scan, load and validate the newest valid one
  (self-digest + root + counts), replay only the records after its root, and fall
  back to an earlier checkpoint or to full replay. `MountReport` measures the
  actual work (records/bytes replayed, wall time, fallback).
* `INDEX_CHECKPOINT` payload extended to embed the full serialized index
  (`src/namespace.rs`), so a checkpoint is a loadable accelerator, not just a
  header. `Namespace::write_index_checkpoint` appends one.
* **Phase-5 carry-over fix** — `src/uring.rs` `BackingRings` now guards both rings
  with a `Mutex` (not a `RefCell`), so `Log` is `Send + Sync` and one `Arc<Log>`
  is shared by many readers/snapshots. `src/log.rs` adds a `RootPins` registry:
  `Log::pin_root(root) -> RootPin` extends the buffer-pool pin discipline to
  committed roots, and `rollover` refuses (`OrfsError::Pinned`, `EBUSY`) to
  quarantine a segment a pinned root still needs.
* Derived `user.orfs.manifested_bytes` and `user.orfs.ekbloom_profile` xattrs
  added (honest `0`/`none`); the root xattrs are documented as references, not
  contents.
* CLI made real: `orfs snapshot list <backing> [--json]`,
  `orfs snapshot inspect <backing> <root> [--json]`, and
  `orfs snapshot mount <backing> <root> <mnt>` (read-only FUSE).
  `fuse::run_snapshot` / `fuse::spawn_snapshot` mount a `Snapshot` core with
  `MountOption::RO`.
* `tests/snapshot_model.rs` — the six required invariants plus a randomized
  `proptest` driver, and the two evidence generators.
* `tests/snapshot_fuse.rs` — a real read-only snapshot mount court
  (`scripts/container-fuse-test.sh` runs it alongside `fuse_integration`).

### What actually works today

```sh
orfs snapshot list    <backing> [--json]
orfs snapshot inspect <backing> <root> [--json]
orfs snapshot mount   <backing> <root> <mnt>      # read-only FUSE
```

* For every committed root `R`, `Replay(L[0:R])` reconstructs the exact
  namespace at `R`; a snapshot never observes a later write.
* Snapshot mounts are read-only (`EROFS`), enforced by the kernel `RO` flag and
  by the read-only `Snapshot` core.
* Checkpoint mount is bit-identical to full replay; a corrupt checkpoint is
  discarded and an earlier checkpoint (or full replay) is used — committed
  history is never silently skipped.
* Mount is **not** constant-time; the measured cost is reported.

## Phase 7 — Concealed manifestation engine and physical accounting

**Complete** (see also `docs/MANIFESTATION.md`). Implements research §2 (I5, I6,
I8), §4, §9, §10, §16, §33. This is Plane C: the concealed operational body.

### Delivered

* `src/manifestation.rs` — the manifestation engine.
  * **Generation identity.** `GenerationManifest` records volume identity, inode
    identity, inode version, authoritative root, EKBLOOM version + format,
    profile, logical range, physical range, construction parameters,
    certification state, integrity (BLAKE3 over the payload **and** a
    self-digest over the canonical fields), physical size, and per-component
    accounting. `usable_for(inode, version, root)` enforces **exact**
    compatibility (I6); a mismatched version is refused, never used.
  * **Job queue + bounded worker pool.** CPU workers construct; `io_uring` never
    does. The queue is bounded and `submit` returns `QueueFull` under
    backpressure — the authoritative commit is never blocked or failed.
  * **Cancellation/supersession.** A newer inode version cancels and supersedes
    older pending jobs; a worker refuses to publish if the inode advanced
    (research §10.3). A cancelled mid-construction job leaves **no** committed
    generation (the partial payload is discarded).
  * **Publication protocol.** payload → manifest (`tmp` + fsync + rename + fsync
    dir) → advertise (`manifests/HEAD`). Recovery selects the newest **valid**
    committed generation per inode; a torn manifest or torn `HEAD` is skipped
    and never invalidates an earlier commit.
  * **Retention/rebuild.** Committed generations are never removed by the engine;
    `sweep_orphans` reclaims only payloads referenced by no committed manifest.
    Dropping all of `.or_bloom/` and rebuilding yields byte-identical **logical**
    reads.
  * **Real construction.** The production builder is `EkbloomBuilder`, which
    consumes the EKBLOOM crate unchanged (`create` + `write_body`); EKBLOOM's
    state machinery is not reimplemented and no EKBLOOM source is copied.
* `src/stats.rs` — physical accounting separating logical from physical: logical
  live bytes/counts, `M_log`, `M_ekbloom`, `M_indexes`, `M_checkpoints`
  (embedded in `or.log`), `M_other`, `M_total`, uncommitted tail bytes, and the
  real backing capacity. The five categories partition the backing directory, so
  `M_total` equals the measured on-disk total exactly. Capacity is never reported
  as unlimited.
* `src/namespace.rs` — manifestation is wired to the commit path: after a
  successful authoritative commit + version publication, jobs are enqueued for
  the regular-file inodes the transaction touched. The foreground never waits
  unless `ManifestationConfig::synchronous` is set. `enable_manifestation` /
  `enable_manifestation_with_builder` start the engine and recover the published
  set; `manifest_eligible` builds/publishes synchronously for the CLI. The
  derived `user.orfs.manifested_bytes` / `user.orfs.ekbloom_profile` xattrs now
  report the version-qualified manifested accounting (a `Snapshot` reports
  `0`/`none`).
* `src/fuse.rs` — `MountOptions` gains `manifest`, `manifest_sync`, and
  `manifest_workers`; `build_core` enables the plane when requested (default:
  disabled, so no existing behaviour changes). `--manifest <profile>`,
  `--manifest-sync`, `--manifest-workers` are exposed on `orfs mount`.
* `src/main.rs` — real `orfs stat <path> [--json]`, `orfs manifest <backing>
  [--inode N] --profile <p> [--depth/--interval/--region-bytes] [--json]`, and
  `orfs grow <backing> --profile <p> [--json]`.
* CLI is honest for a fresh volume: `manifest`/`grow` report `attempted: 0` when
  there are no eligible objects.

**Complete** (see also `docs/EKBLOOM-INTEGRATION.md`). Implements research §10,

### Delivered

* `src/readpath.rs` — the read planner.

    planner when manifestation is enabled (`Namespace::read_at` /

## Phase 9 — Concealed query structures and the typed query API

## Phase 15 — Real FUSE-over-`io_uring` (F2) transport

**Complete.** A real F2 mount is achieved: an OrFS volume mounted with

### Delivered

* **Raw-SQE path (`src/fuse_uring.rs`).** `FUSE_IO_URING_CMD_REGISTER` requires
  `sqe->len == 2` (the iovec count), which the pinned `io-uring` 0.7.15 crate

## Phase 17 — Simulated power-loss durability model

**Complete.** The durability proof obligation left open by Phases 2/11 —
"process crash is not power loss" — is now discharged *relative to a stated
simulated device*. A controlled, deterministic storage layer
(`src/powerloss.rs`, Cargo feature `powerloss`) models a volatile device
write-back cache with configurable `barrier` / `partial` / `reordered_partial`
flushes and optional durable-image damage (`tear_tail` / `lost_watermark`), plus
a `power_fail()` that discards every un-flushed cached write and materialises the
surviving image for an independent recovery. A whole OrFS volume runs on it
through a small no-op-by-default seam (`Segment`, `fsync_dir`, `watermark`).

### Delivered

* **`src/powerloss.rs`** — the deterministic device model (seeded SplitMix64,
sector-granular partial flushes, tunable durable damage, atomic watermark
modelling) and a thread-local attach/lookup registry. Feature-gated
(`powerloss`, on by default; `--no-default-features` compiles a no-op stub at
every seam, so production builds are unaffected).
* **Seams** — `Segment::{create,write_at,sync}`, `segment::fsync_dir`,
`watermark::Watermark::write`, and `log::quarantine_segment` route through the
device when one is attached; nothing changes when it is not.
* **`tests/power_loss.rs`** — 11 tests: for `sync`/`ordered`/`batched`, a
workload of acknowledged mutations is run, power failures are triggered at many
points (with reordering/partial-flush/torn variants), and recovery runs
independently. It asserts the §35 invariants, non-withdrawal, no partial
transaction, the accepted unsynced-ack contract, watermark interaction, and
logical-content consistency.
* **Evidence** — `evidence/recovery/power-loss.json` records, per mode and fault
point, the acknowledged-durable and unsynced roots, surviving durable
mutations, the recovered root/refusal, per-invariant verdicts, and an explicit
`model_assumptions` section.
* **Docs** — `docs/POWERLOSS.md` (new); `docs/RECOVERY.md` §4,
`docs/TRANSACTIONS.md` §4.1/§6.1, and `docs/LIMITATIONS.md` §9 updated.

### Results

Under a device that honours `fsync` (`barrier`), **every** mutation acknowledged
`DURABLE` under `sync` survives a power failure; `batched` survives up to its last
completed sync point; an `ordered` ack without a sync may be absent but never
corrupts committed state. Under contract-violating devices (partial/reordered
flushes, torn durable bytes, a lost watermark) recovery either reaches a valid
committed boundary or **refuses** — never a partially applied transaction, never
a withdrawn byte.

### Honest caveat

The model is a **simulation with assumed device semantics**, not an instrumented
power-loss rig. It does not prove real-hardware durability; `sync` still promises
only what the backing device documents. See `docs/POWERLOSS.md` §5 and
`docs/LIMITATIONS.md` §9.

## Phase 19 — Concurrent immutable read views (remove the global read lock)

**Complete.** External review P0: the FUSE adaptor held `Mutex<core>` across
`getattr()`/`read_at()`, so a read doing physical I/O serialised every other FUSE
request. Reads now go through an **immutable, reference-counted read view** and
hold no lock across I/O.

### Delivered

* **Read view** — `CoreRead` (read-only, `Send + Sync`), `ReadState` (a frozen
  committed root: `Arc<Index>` + `LogView` + the manifested state/planner), and
  `ReadCell = Arc<RwLock<Arc<dyn CoreRead>>>` (`src/namespace.rs`, `src/log.rs`).
  A reader clones the `Arc` out of the cell, drops the guard, and does all I/O
  with no lock held.
* **Publication at the commit boundary** — `Namespace::commit_plan` builds a new
  complete view after extending the index and swaps it in with one store; the
  publication lock is held only for the swap. Readers observe a whole old or new
  state, never a partial one.
* **Index sharing** — inode nodes are `Arc`-shared (`HashMap<u64, Arc<Inode>>`),
  the dentry map is a single `Arc<HashMap<..>>`, and per-directory child maps are
  `Arc<BTreeMap<..>>`. Publication copies only spines (pointer-sized entries), not
  inode payloads; a data-only commit shares the directory structures wholesale.
  See `docs/CONCURRENCY.md` §4.
* **`LogView`** — a captured segment locator plus a shared read-handle cache; the
  cache lock covers only the handle lookup, never the `pread`. Both the live
  engine and the view call the *same* byte-assembly helpers, so they are
  byte-identical.
* **Both transports** — the classical `fuser` read handlers and the native F2
  `Dispatcher` read handlers serve through the view; `Config::n_threads` is set
  from `available_parallelism` so the classical dispatch loop is concurrent.
  Snapshot mounts build a frozen view over the snapshot's own log.

### Results (evidence-backed)

Reader-scaling (`evidence/performance/reader-scaling.json`, 4 MiB file, 16 KiB
reads, 8 CPUs): concurrent-view throughput rises from **1 reader** to **8–16
readers** (e.g. 553 → 1808–2178 MB/s in one run; 343 → 1802–1870 MB/s in
another), while the same workload behind the global core lock stays flat
(≈ 520–634 MB/s). p50/p95/p99 are recorded per reader count. A deterministic
check holds the core lock for ~200 ms while a view read completes in **~20 µs**,
whereas a read taking the core lock waits the whole hold. Three readers spinning
across 150 concurrent commits always observe whole committed versions (size is a
whole number of committed rows; every row carries its own index) and the writer
makes progress. All existing equivalence/model/snapshot/perf courts stay
byte-identical.

### Deferred

Full path-copying of the index map spines (persistent/HAMT maps) — the current
representation is a bounded, measured intermediate that shares nodes and copies
only spines; documented with the plan in `docs/CONCURRENCY.md` §4.1.

## Phase 20 — Persistent historical-root indexes and suffix replay

**Complete.** External review §3D: historical reads paid a full replay per
request, and the live index was re-extended by decoding the whole preceding
stream on every commit.

### Delivered

* **Suffix replay fix** — `Index::apply_range(start, end)` now iterates the suffix
  directly with `Log::records_from(start, end)` (which seeks to `start` and reads
  no byte before it) instead of walking `records_upto(end)` and skipping earlier
  records. `start` must be a committed boundary. `apply_range_traced` reports the
  records and canonical bytes decoded. `checkpoint::mount_index_at` materializes
  an arbitrary committed boundary by loading the newest valid in-log checkpoint at
  or before it and replaying only `[checkpoint_root, root)`.
* **Immutable historical-root cache** — `src/historical.rs`
  (`HistoricalIndexCache`): a bounded in-memory LRU keyed by `(volume uuid, root)`
  (default capacity 8; least-recently-used eviction). A root is materialized once,
  then reused across arbitrarily many lookups/reads. `Namespace::view(root)` now
  resolves non-current roots through it.
* **Persisted derived accelerator** — on materialization the index is written to
  `index/historical/<root>.v1.json` (temp-file + rename), binding schema + uuid +
  root + a BLAKE3 digest over the inner snapshot. On load the uuid, root, envelope
  digest, the inner snapshot's self-digest, and the committed-boundary property are
  re-checked, so the accelerator survives a remount. `Snapshot::from_read_log`
  reuses it too.
* **Log-wins / no invalidation** — snapshots are immutable, so a cached historical
  index is never stale; any absent, torn, tampered, or foreign accelerator is
  dropped and the index rebuilt from the log. Nothing derived ever overrides
  committed history.

## Phase 21 — Kernel-served FUSE passthrough for immutable snapshots

**Complete.** External review §2/§9 (P1): "make the fastest read never invoke
the handler". A read of an immutable historical snapshot file is now answered
directly by the kernel, from a private byte-exact backing file, with no
`FUSE_READ` crossing `/dev/fuse`.

### Delivered

* **Immutable backing images** — `src/passthrough.rs`. For a snapshot file OrFS
  materializes a write-once, digest-verified copy beneath a concealed
  `.or_passthrough/` area, qualified by
  `(volume uuid, committed root, inode, inode version, generation)` and the
  BLAKE3 content digest. The bytes come from the *same* `Snapshot::read_at` code
  path a daemon-served read uses, so equivalence is by construction. The image
  is reused across opens and silently rebuilt if missing/truncated/corrupt.
* **Kernel registration + attach** — `src/fuse_native.rs`. When passthrough is
  requested, the `FUSE_INIT` reply advertises `FUSE_PASSTHROUGH` (`flags2` bit 5)
  and `max_stack_depth = 2`; at `OPEN` the dispatcher registers the backing with
  `FUSE_DEV_IOC_BACKING_OPEN` (ioctl on the session's `/dev/fuse` fd) and replies
  with `FOPEN_PASSTHROUGH` + the returned `backing_id`. Counters on `NativeStats`
  record engagement; `OrfsCore::passthrough_backing` **defaults to `None`** and
  is overridden only by the read-only `Snapshot`.
* **Lifetime + fallback** — registrations are refcounted per image, pinned for
  the open-file lifetime, released on the last `RELEASE` with
  `FUSE_DEV_IOC_BACKING_CLOSE`, and force-released at session teardown. A denied
  registration or materialization error falls back to daemon-served reads with
  identical bytes.
* **Accounting** — `M_passthrough` in `src/stats.rs` counts the concealed images
  and is included in `M_total`.
* **Transports** — passthrough is available only on the native F2 session (the
  only transport that owns `/dev/fuse`); snapshots mounted via `fuser` (F0/F1) or
  on a kernel without `FUSE_PASSTHROUGH` serve reads through the daemon.

### Results (evidence-backed)

All 275 tests pass (was 265; +6 unit tests in `src/passthrough.rs` and
`src/fuse_native.rs`, +4 mount-integration tests in `tests/fuse_passthrough.rs`).
Kernel `7.2.9-2-cachyos`, FUSE ABI 7.45, `CONFIG_FUSE_PASSTHROUGH=y`.

* **Engagement** (`evidence/correctness/fuse-passthrough.json`): after reading a
  256 KiB snapshot file through a real mount, the daemon-side read counter
  `daemon_reads` is **0**, `passthrough_registered = 1`, `passthrough_fallbacks = 0`,
  and a second concurrent open **reuses** the registration (refcount) rather than
  registering again; closing both handles releases it. A denied materialization
  (concealed area forced to be a file) is recorded as a fallback and still returns
  the exact bytes.
* **Byte-exactness**: the kernel-served bytes are byte-identical to an independent
  authoritative replay of the same committed root; a second committed version
  produces a **distinct** image with the correct distinct bytes (no cross-version
  reuse).
* **Latency** (`evidence/performance/passthrough.json`, full-file 256 KiB read):
  passthrough **p50 16.6 µs** vs daemon-served **446 µs** (≈ 27× faster, equal
  bytes) vs cached plain ext4 **3.2 µs**. Residual cost is the FUSE file's
  `read_iter` entry, no longer a `/dev/fuse` round-trip.
* **No regression**: the existing snapshot, transport-equivalence, performance,
  and manifestation courts remain byte-identical; passthrough does not engage for
  a live (mutable) core.

## Phase 22 — Incremental, adaptive generational manifestation

**Complete.** External review §7 (P1): a manifestation job reconstructed the
**entire** logical object into a source buffer even when a transaction changed a
few kilobytes, so `T_build ∝ N` (whole-object size) — the wrong unit of work for
small updates to large objects.

### Delivered

* **Generational extent overlays** — `src/manifestation.rs`. A generation is now
  either self-contained (full base / flattened table) or an **overlay**: a
  qualified `base_generation` plus the newly manifested **changed ranges** only,
  with every unchanged byte reused from the base. `GenerationManifest` schema 2
  adds `base_generation`, `base_manifest_blake3`, `overlay_depth`, and a
  `regions` vector; schema-1 documents still decode.
* **Changed-range capture** — `src/namespace.rs` records the exact logical byte
  ranges each transaction touches (writes, zero ranges, resizes); the enqueue
  path reads only those ranges from the log and the worker builds one small
  EKBLOOM payload per range. A metadata-only change yields an empty-delta overlay.
* **Bounded-depth lookup + adaptive flattening** — `manifestation::resolve_coverage`
  walks the overlay chain at most `MAX_OVERLAY_DEPTH = 8` hops, each base
  digest-verified and inode-qualified. Once `FLATTEN_AFTER_OVERLAYS = 4` overlays
  accumulate (or the cap would be exceeded) the engine publishes an index-only
  **flattened readable view** (complete region table, `overlay_depth = 0`,
  referencing existing committed payloads), leaving authoritative history
  untouched. Region lookup is a binary search.
* **Read correctness** — `src/readpath.rs` resolves an overlay-backed version to
  exactly the authoritative bytes (unchanged regions from the base, changed from
  the overlay), splitting a request across the resolved region table. The first
  read for an identity is verified-on-use against the authoritative read and the
  overlay is barred on any disagreement.
* **Crash-safety** — the publication protocol is unchanged; recovery validates
  each candidate's payloads and accepts an overlay only if its base is already
  accepted, valid, for the same inode, and digest-bound. A cancelled incremental
  job deletes every region payload it wrote.

### Results (evidence-backed)

Construction measured on `ekbloom::create` (CPU construction, excluding fsync),
from `evidence/performance/incremental-manifestation.json`:

|---|---|---|
| 32 KiB | 1.27 ms | 4.2 µs |
| 128 KiB | 5.03 ms | 4.5 µs |
| 512 KiB | 11.44 ms | 3.9 µs |

* The full build grows with the object; the incremental build is **flat** in the

  object the incremental build grows with the changed bytes (64 B ≈ 3 µs, 1 KiB
  ≈ 25 µs, 8 KiB ≈ 175 µs, 32 KiB ≈ 686 µs):
  `T_incremental ≈ T_changed_regions + T_index_update`.
* **Read latency vs generation depth** is flat (~3 µs) across 24 accumulated

  now also records the incremental overlay applied to a small write.
* **Crash mid-incremental-build** (`crash_mid_incremental_build_leaves_no_committed_generation`)
  leaves no committed generation and no orphan region payload; the base alone is
  recovered. **Equivalence** holds across 30 interleaved writes and historical
  snapshots (`overlay_reads_are_authoritative_across_generations_and_snapshots`).
* All tests pass (was 275; +6 Phase-22 courts in `tests/manifestation.rs`,
  including `async_incremental_generations_recover_without_rejection` — the court

## Phase 23 — ENOSPC/device-error recovery hardening and a capacity policy

**Complete.** Production-grade failure handling: running out of authoritative
space, device errors (`EIO`/short writes/failed `fsync`), and reordered durable
writes must never silently violate acknowledged durability; plus a real capacity
policy (research I8, §30, §31).

### Delivered

* **Simulated-device fault injection** — `src/powerloss.rs`. A deterministic
  `DeviceFaultRule { op, kind, skip, fire, name_suffix }` (`DeviceOp` ×
  `DeviceFaultKind`) is consulted by the log's I/O seams (segment `write`/`sync`/
  `create`, directory `fsync`, the commit watermark, and the manifestation
  publish path). A write can be rejected (`ENOSPC`/`EIO`) or **shortened** (a
  partial write then an error). `attach_with_faults` installs a plan.
* **Capacity policy** — new `src/capacity.rs`: a `CapacityPolicy`
  (authoritative **reserve**, optional **soft/hard quotas**, optional explicit
  authoritative bound) and a `CapacityGovernor` with a one-way **degraded latch**.
  When no explicit bound is set the log derives capacity from the backing device
  at open (`available + used`), so the reserve is honoured against the real
  device.
* **Early ENOSPC detection** — `CommitSequencer::projected_transaction_bytes`
  computes the whole framed transaction (`TX_BEGIN` + data + `TX_COMMIT`, each
  with its 60-byte header and 16-byte footer) and `Log::ensure_capacity` admits it
  **before the first byte is written**; `Log::reserve` re-checks per record.
* **Read-only transition** — an authoritative `ENOSPC`/`EIO` latches the volume
  degraded: the failing operation is not acknowledged, the root does not advance,
  no committed byte is rewritten, and every further mutation returns `EROFS`.
  Reads continue. `OrfsError::is_authoritative_store_failure` classifies the
  trigger; `OS ENOSPC` is mapped to `OrfsError::NoSpace` at the segment seam.
* **Optional-first throttling** — `Namespace::commit_plan` asks
  `optional_allowed(authoritative, optional)` before enqueuing any manifestation
  or trigram job, so optional construction stops before it can starve
  authoritative commits. An optional failure is recorded (`Failed`/`Skipped`) and
  never fails an authoritative commit.
* **Reordered durable writes** — `FlushMode::Reordered` (an honoured barrier that
  applies durable writes out of order: nothing is lost) and
  `DurableLoss::ReorderDurable` (a contract-violating device drops durable sector
  blocks; safety-only).
* **Diagnostics** — `stats::PhysicalAccounting` and `orfs stat` report the policy,
  reserve, quotas, authoritative usage, admissible headroom, optional usage,
  throttle state, and degraded reason; the FUSE `--reserve` mount flag sets a
  reserve.

### Results (evidence-backed)

* Every authoritative write, sync, rollover, and watermark point swept with
  `ENOSPC` (`evidence/recovery/enospc.json`, 19 cases) and with `EIO`/short
  write/failed `fsync` (`evidence/recovery/device-error.json`, 32 cases): every
  case recovers to a complete committed boundary, every acknowledged-durable
  mutation survives, no partial transaction is ever visible, and the volume

## Phase 25 — Close the pjdfstest POSIX deviations

**Complete.** Implements the Linux/POSIX semantics the Phase 24 pjdfstest court
exposed (external-review finding P1), then re-runs the court to prove the
deviation count dropped.

### Delivered

* **Implicit timestamps** (`src/namespace.rs`). A namespace mutation (`create`,
  `mkdir`, `symlink`, `link`, `unlink`, `rmdir`, `rename`) now advances the
  containing directory's `mtime`/`ctime`, and a content mutation (`write`,
  `truncate`, `ftruncate`, `O_TRUNC`) advances the file's `mtime`/`ctime`. Each
  update is an appended `INODE_SETATTR` record in the *same* transaction as the
  mutation (`Plan::bump_times`), so committed history is never rewritten and a
  snapshot pinned to an earlier root reads exactly the timestamps that root
  encoded. Explicit `utimensat`/`UTIME_NOW`/`UTIME_OMIT` values are preserved.
* **`setuid`/`setgid` on write/truncate** (`src/fuse.rs`, `src/fuse_native.rs`,
  `src/namespace.rs`). Both transports now negotiate `FUSE_HANDLE_KILLPRIV` and
  `FUSE_HANDLE_KILLPRIV_V2`; the daemon clears `S_ISUID`/`S_ISGID` in the same
  transaction as the write flagged `FUSE_WRITE_KILL_SUIDGID`, and on a truncate
  by a caller without `CAP_FSETID` (`OrfsCore::write_at_killpriv`).
* **`utimensat(UTIME_NOW)` with write permission** (`src/fuse.rs`,
  `src/fuse_native.rs`). A pure `ATTR_TOUCH` update now needs only write
  permission for a non-owner (`EACCES` when absent, not `EPERM`).
* **`ftruncate` through a writable fd** (`src/fuse.rs`, `src/fuse_native.rs`). A
  `SETATTR` carrying an already-open writable handle no longer re-checks the
  inode's write permission.
* **Supplementary-group `chgrp`** (`src/fuse.rs`, `src/fuse_native.rs`). A
  non-root owner may `chgrp` to its effective or a supplementary group, read from
  the kernel's `/proc/<pid>/status` `Groups:` line; unconfirmable membership is
  refused with `EPERM`.

## Phase 27 — Fix publish `O(N²)` churn; large-scale endurance and recovery acceleration

### The defect and its fix

The Phase-19 read-view publication was meant to *share* structure, but it shared
mutable containers: `inodes`/`dentries`/`children` were `HashMap`/`Arc<HashMap>`
spines that were fully copied on every publish, and `Arc::make_mut` on a shared
inode deep-copied that inode's ever-growing `versions: Vec<InodeVersion>`. Because
a busy directory's version vector grows without bound (and unlinked inodes are
retained), sustained `create`/`rename`/`unlink` churn was `O(history²)`.

Phase 27 replaces the shared-mutable representation with **persistent,
path-copying structures** (`src/persistent.rs`):

* `inodes`, `children` and `snapshots` are persistent treaps (`PMap`); a commit
  path-copies `O(log n)` nodes and shares every untouched subtree; cloning an
  `Index` for publication is a handful of `Arc` bumps.
* `Inode.versions` is a shared `VersionHistory` (an `Arc`-linked newest-first
  list); appending is `O(1)` and never deep-copies the prior history.
* `Inode.extents` is an `ExtentMap` over `PMap<u64, Extent>` with an incremental
  overlay, so writes stay `O(log E + k)` and a file with very many extents is not
  re-copied on every write.

The observable index is unchanged (same records, same canonical digest, same
byte-for-byte snapshot document), so every correctness court and historical
reconstruction remains exact.

### Measured results (`benches/endurance.rs`, `scripts/container-endurance.sh`)

* **Publish cost is flat:** the index-clone publication step is ≈**60 ns** at
  10k, 100k and 1M churn iterations; per-iteration commit p50 stays ≈45–59 µs
  across the 100× history increase; 1M iterations (3M ops) complete in ≈63 s with
  0 errors. `evidence/performance/publish-cost.json`.
* **Endurance:** 1 001 025 retained inodes, ≈959 MiB RSS (≈1 KiB/inode, linear,
  within the 8 GiB cap), 1 741 MB log, 0 errors. A file grown to **199 999**
  disjoint extents (100 000 writes) keeps write p50 ≈6.4–8.9 µs and read p50
  ≈0.7 µs. **2 000** historical roots open/verify with 0 errors. 4 remounts
  interleaved with 4 concurrent readers: 297 342 reads, 0 errors, monotone roots.
  `evidence/performance/endurance.json`.
* **Recovery acceleration:** mount is `Θ(history)` in every mode. Without a
  checkpoint the whole log is replayed (20/74/312 ms at 0.5k/2k/8k commits); with
  a valid checkpoint `bytes_replayed` collapses (17→1.2 MB, 271→16.8 MB) but a
  whole-log discovery scan and the embedded-index decode remain, so the win is a
  crossover (60 ms vs 74 ms at 2 k; a wash at 8 k) — reported honestly, not
  claimed constant-time. `evidence/performance/recovery-acceleration.json`.

## Phase 28 — Native FUSE adversarial hardening and fuzzing

Phase 11's fuzzing covered the record/log and the FUSE-over-`io_uring` *header*
decoder; the external review (§5) observed that the native FUSE code
(`src/fuse_native.rs`, `src/fuse_uring.rs`) is the crate's most `unsafe`-dense
surface and that its "safety comments are documentation, not a proof of
soundness". Phase 28 gives that surface dedicated fuzzing, sanitizer coverage,
and explicit tests of buffer lifetimes, SQE layout, and completion ownership.

### Fuzzer (`tests/native_fuse_fuzz.rs`)

A deterministic, seeded, bounded in-container mutation fuzzer (the
`tests/fuzz_decode.rs` method, specialised to the native transport). It starts
from valid encodings and applies bit flips, byte overwrites, truncation,
splicing, extreme length words, and zero runs, plus fully random strings; every
decoder is total (fixed-size field copies, no input length sizes an allocation).

* seed `0x0F35_28FF_7E5E_0001`; **110 000 iterations, 0 panics**: `FuseInHeader`
  decode 40 000; `FuseUringReqHeader`/`RingRequest` decode 40 000 (hostile ring
  entries: out-of-range `nodeid`/`offset`, zero/oversized `payload_sz`, bogus
  `commit_id`/`flags`); 80-byte SQE command area 20 000; reply encode 10 000.
* `evidence/security/native-fuse-fuzz.json`.

### Completion ownership + buffer lifetime (explicit tests)

Each asserts the invariant its neighbour comment claims:

* **Reply over-claim (fixed).** `write_reply` copied the reply body with
  `payload[..data.len()]` and published `data.len()` as the kernel-visible
  `payload_sz` without capping it at `PAYLOAD_BUF` (256 KiB). A hostile/buggy
  `read`/`readdir` `size` made the session thread **panic** (DoS) and would have
  made the kernel copy past the registered buffer. Fixed by clamping; the
  request-side clamp is now the single tested `clamp_payload_sz`.
* Reused-buffer reply encoding is byte-identical under interleaving
  (`reply_encode_into_interleaved_reuse_is_byte_identical`); header/payload
  offsets are asserted (`write_reply_stages_header_and_payload_at_documented_offsets`).
* `EntryState` buffers keep a stable address and `iov` array across an ownership
  move to another thread (`entry_state_buffers_are_stable_under_ownership_move`;
  `buffers::tests::aligned_buffer_address_is_stable_when_ownership_moves_between_threads`).
* `WorkerPool::drop` joins every worker with outstanding jobs before the ring and
  entries are torn down; a closed `JobQueue` drains to `None`
  (`worker_pool_drop_joins_workers_with_outstanding_jobs`,
  `job_queue_close_wakes_waiters_and_drains_cleanly`).
* A registered buffer is releasable only after every referencing completion is
  reaped and its pin dropped — a cancel is not a completion
  (`buffers::tests::registered_buffers_are_released_only_after_every_completion_is_reaped`).
* Raw 128-byte SQE layout: `size_of::<Entry128>() == 128`, and
  `entry128_set_len` writes only byte offset 24 for several values
  (`fuse_uring::tests::raw_sqe_len_field_is_written_at_the_documented_offset`);
  the command area decodes totally over arbitrary bytes
  (`cmd_area_decode_is_total_over_arbitrary_bytes`).
