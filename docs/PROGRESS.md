## Phase 1 — Authoritative append-only log

**Complete** (see also `docs/ON_DISK.md`, `docs/LOG-INVARIANTS.md`).

### Delivered

* `src/record.rs` — versioned record envelope: 60-byte header, opaque payload,
  16-byte footer, little-endian explicit field codecs, CRC32C header and record
  checks, checked length arithmetic, bounded allocation, and a full
  `RecordType` enum with mandatory/optional classification.
* `src/segment.rs` — immutable `NNNNNNNNNNNNNNNN.seg` segments, segment-name
  parsing/discovery, append-only writer, positional reads, and `SegmentLocator`
  (contiguous logical-offset → `(segment, physical offset)` mapping).
* `src/log.rs` — the canonical append-only stream: reserve-then-write
  reservations, fsync hooks, transaction lifecycle (`begin`/`commit`/`abort`),
  `replay_upto`, `records_upto`, committed-root publication, physical-tail
  quarantine, and `scan_log` validation/diagnostics.
* `src/volume.rs` — `volume.meta` identity, `init`/`open`, segment discovery,
  genesis payload, and `verify`.
* `src/main.rs` — `orfs init`, `orfs inspect [--json]`, `orfs verify [--deep]`,
  and `orfs recover` are genuinely implemented; later-phase commands remain
  honest `ENOSYS` stubs.

### What actually works today

```sh
orfs init <dir> [--segment-size N]   # create volume.meta + genesis
orfs inspect <dir> [--json]          # identity, segments, root, accounting
orfs verify [--deep] <dir>           # authoritative structure checks
orfs recover <dir>                   # quarantine an abandoned tail, report
```

* A root `R` is a logical committed end offset; every published root is a
  complete transaction boundary.
* Torn or uncommitted tails are retained and quarantined, never truncated;
  writes continue in a fresh segment.
* Replay from any committed prefix is deterministic.

## Phase 2 — Transactions, commit sequencer, durability, fault injection

**Complete** (see also `docs/TRANSACTIONS.md`).

### Delivered

* `src/transaction.rs` — the transaction model: explicit states (`PREPARED`,
  `RESERVED`, `SUBMITTED`, `DATA_COMPLETED`, `COMMIT_COMPLETED`, `PUBLISHED`,
  `DURABLE`, `FAILED`) with an enforced forward-only transition relation; typed,
  CRC32C-checked payload codecs for `TX_BEGIN` (28 B), `TX_COMMIT` (72 B, with a
  BLAKE3 bracket checksum and commit sequence number), and `TX_ABORT`
  (variable-length, with a reason); and a `TransactionBuilder` that validates all
  arguments before anything is reserved.
* `src/commit.rs` — the single authoritative commit sequencer:
  validate → build → reserve → write data → wait for completions → write/validate
  `TX_COMMIT` (read back from the backing store) → publish the in-memory root →
  reply per durability mode. The root is published **only** after `TX_COMMIT` is
  fully written and validated, so no reader can observe a partial transaction.
* Durability profiles with documented acknowledgment contracts:
  `sync` (ack after `fsync`; `DURABLE`), `ordered` (ordered + published; no
  commit-time `fsync`; `PUBLISHED`), `batched` (coalesced sync points with an
  explicit contract). No profile claims power-loss durability
  (`claims_power_loss_durability()` is always `false`).
* `src/failpoints.rs` — a reusable failpoint system behind the `failpoints`
  Cargo feature (compile-time no-op by default), with thread-local runtime
  control via environment variables or `configure`/`configure_one`/`clear`, and
  `error`/`abort` actions, at all ten required injection points plus directory
  synchronization.
* `tests/transaction_model.rs` — builder/codec validation, the state machine,
  bracket verification, durability contracts, rollover, all failpoints
  in-process (terminate → drop → reopen → verify), and randomized
  transaction/failpoint sequences (proptest).
* `tests/crash_recovery.rs` — **process-crash** tests: a child process is killed
  with `SIGABRT` at each failpoint and the volume is reopened in an independent
  step; every recovery invariant is checked and recorded as evidence.
* `tests/support/mod.rs` — shared recovery-verdict helpers.

### Explicitly not implemented in Phase 2

## Phase 3 — Namespace engine, extents, rebuildable index

**Complete** (see also `docs/NAMESPACE.md`).

### Delivered

* `src/inode.rs` — the versioned inode model (stable id, generation, type,
  mode/permissions, uid/gid, link count, logical length, timestamps, xattr map,
  current and historical versions, latest authoritative record offset) and the
  inode-scoped payload codecs (`INODE_CREATE`, `SYMLINK_CREATE`,
  `INODE_METADATA`, `PERMISSION_CHANGE`, `INODE_SETATTR`, `XATTR_SET`,
  `XATTR_REMOVE`). Names are not part of identity.
* `src/directory.rs` — `(parent,name) → child` relations and the namespace
  payload codecs (`DENTRY_ADD/REMOVE/RENAME`, `HARDLINK_ADD/REMOVE`).
* `src/extent.rs` — the logical extent map: offset-zero, middle, EOF,
  beyond-EOF (POSIX zero-fill), overlapping, sparse, and partial writes;
  truncate shrink (append `FILE_RESIZE`, never reclaim) and extend (zero-fill,
  never resurrect); explicit `DATA_ZERO_RANGE`. Overwrites append new immutable
  data and never rewrite historical storage.
* `src/index.rs` — the derived, rebuildable namespace index (inode→version,
  `(parent,name)→child`, extent map, xattr map, root→snapshot), built purely by
  replaying the log, with a canonical digest and an optional validated
  accelerator snapshot under `index/`. The log always wins.
* `src/namespace.rs` — the engine and the transport-neutral `OrfsCore` trait
  (lookup/read/write/create/mkdir/unlink/rmdir/rename/link/symlink/readlink/
  getattr/setattr/getxattr/setxattr/listxattr/removexattr/readdir, plus
  `read_at`/`write_at`) that the Phase-4 FUSE layer will call.
* Carry-over fix (a): typed `TX_BEGIN`/`TX_COMMIT` bracket validation in
  recovery and `orfs verify --deep`; an inconsistent committed bracket is a hard
  error.
* Carry-over fix (b): transaction ids are allocated strictly monotonically above
  every id ever observed (including aborted ids), across reopen.
* `orfs verify --deep` additionally reports typed-bracket validation and a
  deterministic namespace-index rebuild.

## Phase 4 — Traditional FUSE transport and POSIX semantics

**Complete** (see also `docs/FUSE-SEMANTICS.md`).

### Delivered

* `src/fuse.rs` — a real `fuser::Filesystem` implementation over the
  transport-neutral `OrfsCore` (typed `fuser` 0.18 API). It owns only POSIX
  transport bookkeeping: the inode/handle split, lookup accounting, directory
  iteration cookies, permission checks, cache invalidation, and errno mapping.
  `MountOptions` exposes the cache profile (TTLs, `direct_io`, readahead,
  `max_write`), `default_permissions`, `allow_other`, read-only, and the
  `statfs` accounting mode.
* All mandatory operations are implemented: `init`, `destroy`, `lookup` (with
  `.`/`..`), `forget`, `getattr`, `setattr`, `opendir`, `readdir`,
  `readdirplus`, `releasedir`, `open`, `read`, `write`, `flush`, `fsync`,
  `fsyncdir`, `release`, `create`, `mknod`, `mkdir`, `unlink`, `rmdir`,
  `rename` (+`NOREPLACE`/`EXCHANGE`), `link`, `symlink`, `readlink`, `getxattr`,
  `setxattr`, `listxattr`, `removexattr`, `statfs`, `access`, `fallocate`,
  `lseek` (`SEEK_DATA`/`SEEK_HOLE`), `copy_file_range`.
* Semantics guaranteed by tests: inode identity is separate from open-handle
  identity; unlink-while-open keeps existing handles functional; directory
  iteration has stable cookies with a documented snapshot-consistency policy;
  `flush` is not a durability barrier while `fsync` is; permissions are
  enforced consistently across lookup/read/write/xattr/mutations.
* Cache profile: conservative **write-through** with 1 s entry/attr TTLs and
  explicit invalidation sent from a dedicated thread; `direct_io`/readahead are
  options. The writeback cache is **not** enabled (documented in
  `docs/FUSE-SEMANTICS.md` §8).
* `src/main.rs` — `orfs mount <backing> <mnt> --transport fuse --backing-io
  <sync|uring> --durability <sync|ordered|batched> [cache options]` and
  `orfs unmount <mnt>` are real. `--transport fuse-uring` is rejected with
  `ENOSYS` (Phase 5); `--backing-io uring` is accepted and honestly falls back
  to synchronous I/O with a warning.
* `src/namespace.rs` — `OrfsCore` gained `root`, `parent_of`, `zero_range`,
  `seek_data_hole`, and `sync`, implemented by `Namespace`.
* `scripts/container-fuse-test.sh` — runs the FUSE court through
  `docker_run_kmount` (`--device /dev/fuse`, `--cap-add SYS_ADMIN`, unconfined
  AppArmor/seccomp), one container at a time. `scripts/lib.sh`'s
  `docker_run_kmount` now bind-mounts a generated `/etc/passwd` so the setuid
  `fusermount3` helper can resolve the host uid.
* Carry-over fix (test-only): the reference model in `tests/namespace_model.rs`
  no longer extends a file on a zero-length write (POSIX: a zero-length write
  never changes the file). The counterexample is retained in
  `tests/namespace_model.proptest-regressions`.

### Declared-unsupported in Phase 4

* `getlk`/`setlk`/`flock` return `ENOSYS` and the POSIX/flock capabilities are
  not negotiated: the kernel's local lock manager services them, which is correct
  for a single-node mount (documented in `docs/FUSE-SEMANTICS.md` §9).
* `mknod` of non-regular/non-directory types (`EOPNOTSUPP`); `fallocate`
  collapse/insert/unshare (`EOPNOTSUPP`); `RENAME_WHITEOUT` (`EOPNOTSUPP`).
* FUSE-over-`io_uring` transport, `io_uring` backing I/O, writeback cache,
  passthrough (later phases).
